# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a toggleable dark mode to the Brain Visualizer frontend, persisted in localStorage, controlled by a floating button in the top-right of the main canvas.

**Architecture:** Install `next-themes` to manage dark/light state. It toggles the `dark` class on `<html>`, reads/writes `localStorage`, and handles SSR hydration. Tailwind's `dark:` variants then activate based on that class. All component dark mode changes are additive — existing light-mode classes stay, `dark:` counterparts are appended.

**Tech Stack:** Next.js 15, React 19, Tailwind CSS 3.4, `next-themes`, `lucide-react` (already installed)

## Global Constraints

- Dark mode toggled via `.dark` class on `<html>` (Tailwind `darkMode: 'class'`)
- `next-themes` version: install latest (`npm install next-themes`)
- UCLA blue (`#2774AE`) brand color is **not changed** in either mode — only neutral gray/white surfaces get dark variants
- `MRIPlaybackModal.tsx` and `LeftSidebar.tsx` are **not modified**
- `globals.css` is **not modified** — its `.dark {}` block is already complete
- Working directory for all frontend commands: `frontend/`

```tsx
import type { Metadata } from "next";
import { Geist, Geist_Mono } from "next/font/google";
import { ThemeProvider } from "next-themes";
import "./globals.css";

const geistSans = Geist({
  variable: "--font-geist-sans",
  subsets: ["latin"],
});

const geistMono = Geist_Mono({
  variable: "--font-geist-mono",
  subsets: ["latin"],
});

export const metadata: Metadata = {
  title: "Brain Visualizer",
  description: "UCLA Brain Visualizer",
};

export default function RootLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body className={`${geistSans.variable} ${geistMono.variable} antialiased`}>
        <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
          {children}
        </ThemeProvider>
      </body>
    </html>
  );
}
```

Note: `suppressHydrationWarning` on `<html>` is required by next-themes — it prevents React from warning about the `class` attribute being set during hydration.

## Task 2: ThemeToggle component + viewer integration

**Files:**
- Create: `frontend/src/components/ThemeToggle.tsx`
- Modify: `frontend/src/app/viewer/page.tsx`

**Interfaces:**
- Consumes: `useTheme` from `next-themes`; `Sun`, `Moon` from `lucide-react`
- Produces: `<ThemeToggle />` — a self-contained button, no props needed

- [ ] **Step 1: Create ThemeToggle.tsx**

Create `frontend/src/components/ThemeToggle.tsx`:

```tsx
'use client';

import { useTheme } from 'next-themes';
import { useEffect, useState } from 'react';
import { Sun, Moon } from 'lucide-react';

export default function ThemeToggle() {
  const { resolvedTheme, setTheme } = useTheme();
  const [mounted, setMounted] = useState(false);

  useEffect(() => {
    setMounted(true);
  }, []);

  if (!mounted) return null;

  const isDark = resolvedTheme === 'dark';

  return (
    <button
      onClick={() => setTheme(isDark ? 'light' : 'dark')}
      className="rounded-full p-2 bg-white/80 dark:bg-gray-800/80 backdrop-blur-sm shadow-md text-gray-700 dark:text-gray-200 hover:bg-white dark:hover:bg-gray-700 transition-colors"
      title={isDark ? 'Switch to light mode' : 'Switch to dark mode'}
      aria-label={isDark ? 'Switch to light mode' : 'Switch to dark mode'}
    >
      {isDark ? <Sun className="w-5 h-5" /> : <Moon className="w-5 h-5" />}
    </button>
  );
}
```

Use `resolvedTheme` (not `theme`) — when `defaultTheme="system"`, `theme` returns `'system'` until the user makes an explicit choice, while `resolvedTheme` always gives the actual active mode (`'dark'` or `'light'`). The `mounted` guard prevents the icon from rendering during SSR, avoiding a hydration mismatch where the server doesn't know the user's saved theme.

- [ ] **Step 2: Mount ThemeToggle in viewer/page.tsx**

In `frontend/src/app/viewer/page.tsx`, add the import at the top:


Find the returned JSX. There is a top-level wrapper `div` containing the sidebar, the iframe/canvas area, and the panel overlays. Add `ThemeToggle` positioned absolute in the top-right of the main content area. Add it just before the closing tag of the outermost `div`:

Place this right before the final `</div>` that closes the outermost return wrapper, so it floats above all other content.
